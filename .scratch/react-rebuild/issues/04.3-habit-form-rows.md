# 04.3: Habit form fields stop stretching

**Parent:** 04 (Habits page)

**What to build:** The add/edit habit form lays its fields on a wrapping row with
`align-items: flex-end`, which stretches the name input to the height of the
tallest thing on the row. Third instance of this defect (study 06.3, projects
05.3). Name gets its own row; the three targets are small and related, so they
keep sharing one.

**Blocked by:** 04 (Habits page) — done

**Status:** done (2026-09-13)

- [x] Name input on its own row, no longer stretched
- [x] Daily/weekly/monthly targets share a row
- [x] Buttons share a row at the end
- [x] Add and edit forms match

**Note:** each feature carries its own copy of these form styles, which is why
this defect has now been fixed three times. A shared form-layout module would
stop the fourth.
