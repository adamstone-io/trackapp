# 05.1: Task delete cascades its time entries away

**Parent:** 05

**What to decide/build:** Ticket 05 shipped permanent task delete (checklist: "Task CRUD: … delete") behind an inline confirmation that warns "N logged entries are deleted with it" — because `TimeEntry.task` is `on_delete=CASCADE` (`backend/tracker/models.py`), so deleting a task destroys its tracked history. This sits oddly against spec story 16's rationale ("so that I don't lose task history" — projects carefully unassign via SET_NULL) and the repo rule "never hard delete user data". The legacy app never hard-deletes tasks (its Delete button archives). Options: (a) keep as-is — the warning is explicit and archive is the default action; (b) make task delete refuse when `entry_count > 0` (archive instead); (c) change the FK to SET_NULL and let entries keep their `task_title` snapshot.
